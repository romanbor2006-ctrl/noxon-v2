# Telegram-бот нагадувань noxon — дизайн

Дата: 2026-09-22 · Статус: погоджено в чаті, очікує перегляду файлу

## Мета

Дмитро забуває про дати повернення. Бот раз на день перевіряє борги й пише
в Telegram, коли до дати повернення лишилось 3 дні, 1 день або настав сам
день. Решту часу мовчить.

**Експеримент:** поки що отримувач один — Роман. Повідомлення написані так,
ніби він на місці Дмитра, і охоплюють **усі** відкриті борги Дмитра. Пізніше
отримувача міняють на Дмитра, нічого більше не змінюючи.

## Що бот робить і чого не робить

- Надсилає одне повідомлення на день, лише якщо щось горить.
- Пороги — рівно 3, 1 і 0 днів до дати повернення. Після дати бот мовчить.
- Лише надсилає: жодних команд, кнопок і відповідей на повідомлення.
- Нічого не пише в базу.

## Архітектура

```
GitHub Actions (розклад)
   └─ bot/remind.js
        1. анонімний вхід у Firebase Auth (REST, як «Увійти як гість»)
        2. читає колекцію debts (Firestore REST)
        3. рахує через storage.js сайту
        4. відбирає борги з 3 / 1 / 0 днів до дати
        5. нічого — вихід; є — одне повідомлення в Telegram
```

### Файли (у репозиторії `noxon-v2`)

| Файл | Відповідає за |
|---|---|
| `bot/load-site.js` | завантажує `config.js` і `storage.js` сайту в Node через `vm` зі стабами `window`/`localStorage`; віддає `Store.calc` і `Store.state` |
| `bot/firestore.js` | анонімний вхід (`identitytoolkit accounts:signUp`) і читання `debts` (`firestore.googleapis.com`), перетворення типізованих значень REST у звичайні об'єкти |
| `bot/reminders.js` | чиста логіка: `pickDue(debts, calc)` → групи «Сьогодні / Завтра / Через 3 дні»; `formatMessage(groups, opts)` → HTML-текст для Telegram |
| `bot/telegram.js` | `sendMessage(token, chatId, html)` |
| `bot/remind.js` | точка входу: режими, час, збирання всього разом |
| `bot/chat-id.js` | допоміжний: показує chat ID за токеном (запускає людина локально) |
| `bot/reminders.test.js` | автотести на `node --test` |
| `.github/workflows/remind.yml` | розклад і ручний запуск |

Залежностей npm немає: Node 20+ має `fetch` і `node:test`.

### Доступ до даних

Бот заходить **анонімно**, як гість сайту. Правила вже дозволяють гостю
читати `debts`, `site`, `ratings` і забороняють `users` та будь-який запис.
Жодних ключів сервісного акаунта Firebase. Публічні `apiKey` і `projectId`
бот бере з `config.js`.

Анонімні акаунти накопичуються (один на запуск); Firebase видаляє їх сам
через 30 днів (Auto clean-up увімкнено).

### Математика

Бот не дублює формули: `load-site.js` виконує `config.js` і `storage.js`
у пісочниці `vm`, записує борги в `Store.state.debts` і користується
`Store.calc` (`isOpen`, `left`, `paid`, `daysLeft`). Так «днів до дати» і
«лишилось» завжди збігаються з сайтом.

### Час

- Workflow запускається двічі: `0 6 * * *` і `0 7 * * *` (UTC).
- Змінна `TZ=Europe/Kyiv`, тож «сьогодні» — київська дата.
- У режимі `normal` скрипт працює, лише якщо в Києві зараз 9-та година; інший
  запуск завершується без дій. Так 9:00 тримається і влітку, і взимку.
- Затримку GitHub (5–30 хв) приймаємо.

## Повідомлення

HTML (`parse_mode: HTML`), увесь текст із бази екранується (`& < >`).

```
🔺 noxon: наближаються дати повернення

Сьогодні
• Ростик — 1 000 ₴ за «шаурма і проїзд»
  (з 1 500 ₴ уже повернуто 500)

Завтра
• Олег — 3 000 ₴ за «на новий телефон»
  (Дмитро заявив, що віддав 1 000 ₴, — чекає підтвердження)

Через 3 дні
• Ростик — 6 000 ₴ за «оренда за місяць»

Разом у ці три дні: 10 000 ₴
noxon-app.vercel.app
```

Правила:
- Групи — «Сьогодні», «Завтра», «Через 3 дні»; порожні не показуються.
- Сума — те, що лишилось (`calc.left`); якщо були платежі — рядок «з X уже повернуто Y».
- Заявка `claim` без підтвердження — окремий рядок.
- Імена кредиторів справжні.
- Ім'я героя в рядку заявки — з `site/subject` (перше слово імені); якщо досьє
  немає — «Герой сайту».

У кожну групу потрапляє борг, лише якщо `calc.isOpen(d)` (статус `approved`
і `left > 0`) і `calc.daysLeft(d)` дорівнює 0, 1 або 3.

## Режими

| Режим | Де | Що робить |
|---|---|---|
| `normal` | розклад | перевірка години; надсилає, лише якщо щось горить |
| `test` | ручний запуск | без перевірки години; надсилає завжди; якщо нічого не горить — «Нічого не горить. Найближче: …» |
| `--dry-run` | локально | нічого не надсилає, друкує текст у консоль; токени не потрібні |

## Секрети

GitHub → Settings → Secrets and variables → Actions:
- `TELEGRAM_BOT_TOKEN` — токен від @BotFather. Людина вводить сама.
- `TELEGRAM_CHAT_ID` — chat ID отримувача.

У код і журнали секрети не потрапляють.

## Помилки

- Будь-яка помилка Firebase чи Telegram → зрозумілий текст у журналі й
  ненульовий код виходу; запуск стає червоним, GitHub надсилає лист.
- Немає секретів у `normal`/`test` → помилка з назвою відсутнього секрету.
- Telegram `403` (бот не запущений користувачем) → підказка «натисни Start у боті».

## Перевірка

Автотести (`node --test bot/`), фіксована «сьогоднішня» дата:
- 3, 1, 0 днів — потрапляють у свої групи;
- 2 дні, прострочені, закриті, `pending`, `rejected` — не потрапляють;
- часткові платежі й висяча `claim` — правильні рядки;
- екранування HTML у причині й імені;
- порожній результат → `null` у `normal`, «Нічого не горить…» у `test`.

Ручна: `node bot/remind.js --dry-run` проти живої бази; потім ручний запуск
workflow у режимі `test`.

## Відомі обмеження

- Розклад GitHub може запізнюватися; повідомлення «близько 9:00».
- Після 60 днів без комітів GitHub вимикає розклад; вмикається одним кліком.
- Ручний запуск у той самий день може надіслати повідомлення вдруге.

## Поза межами

Команди бота, кнопки, нагадування кредиторам, нагадування про прострочене,
кілька отримувачів, запис у базу.
