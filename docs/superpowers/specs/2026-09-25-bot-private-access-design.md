# Бот лише для своїх: прив'язка акаунтів, особисті команди й сповіщення

Етап 1 удосконалення Telegram-бота @noxonV2_bot. Бот лише **показує й
повідомляє**; усі дії (підтвердити платіж, заявити повернення, новий борг)
лишаються на сайті. Модерація заявок для адміна — як була.

## Доступ

- Бот відповідає лише чатам, прив'язаним до **активного** акаунта сайту з
  роллю `member`, `admin` або `subject`. Гості сайту (анонімні) прив'язатися
  не можуть. Вимкнений адміном акаунт втрачає доступ одразу (перевірка на
  кожне повідомлення).
- Чат адміна з `TELEGRAM_ADMIN_CHAT_ID` зберігає модерацію (`/zayavky`,
  кнопки) навіть без прив'язки.
- Чужим бот відповідає лише «Це приватний бот noxon…» і кнопкою на сайт —
  жодних даних.

## Прив'язка

1. На сайті в картці «Оплата і підтримка» — рядок «Telegram-бот» зі статусом
   і кнопкою **«Підключити Telegram»** (для гостя прихований).
2. Натискання генерує в браузері випадковий код (32 символи, crypto),
   відкриває `https://t.me/noxonV2_bot?start=<код>` і записує документ
   `tglinks/<код> = { uid, ts }`.
3. Бот отримує `/start <код>`, читає `tglinks/<код>` акаунтом бота (адмін),
   перевіряє вік ≤ 15 хв і активність користувача, записує
   `telegram/<uid> = { chatId, name, ts }`, прибирає інші прив'язки цього
   чату, видаляє код. Код одноразовий. Якщо код ще не записався — одна
   повторна спроба через ~1,5 с, далі «натисни ще раз на сайті».
4. Відв'язати: кнопка на сайті (видаляє `telegram/<uid>`) або `/vidvyazaty`.

## Правила бази

- `tglinks/{code}`: create — активний не-гість, `code` = `[A-Za-z0-9]{24,48}`,
  поля лише `uid` (= свій) і `ts` (свіжий); read/delete — адмін; update — ніхто.
- `telegram/{uid}`: read — сам власник або адмін; create/update — адмін
  (бот), поля `chatId`(string ≤ 20), `name`(string ≤ 40), `ts`(int);
  delete — сам власник або адмін.
- `tgsent/{id}`: лише адмін (позначки надісланих сповіщень).

## Команди (для прив'язаних)

Кнопки клавіатури: «📋 Борги», «📊 Стан», «ℹ️ Допомога».
Команди: `/borhy`, `/stan`, `/help`, `/vidvyazaty`.

- **Борги** — кредитор: що Дмитро винен саме йому (залишок, дата, частково
  повернуто, чи є заявка «віддав» на підтвердження) і його заявки на розгляді.
  Дмитро: усі відкриті борги в порядку черги з позначкою прострочення.
- **Стан** — загальний борг, прострочене, індекс надійності, найближча дата.
  Математика — та сама, що на сайті (storage.js через vm).
- Під відповідями — кнопки «🔗 Відкрити сайт», для Дмитра ще «💸 Віддати».

## Сповіщення (події)

| Подія | Кому | Ключ позначки |
|---|---|---|
| Заявку підтверджено / відхилено | кредитору-автору | `st_<debt>_<status>` |
| Новий підтверджений борг | Дмитру | `new_<debt>` |
| Дмитро заявив «віддав X» | кредитору | `cl_<debt>_<claim.ts>` |
| Кредитор підтвердив платіж | Дмитру | `pay_<debt>_<payment.ts>` |

- Чиста функція `collectEvents(debts, users)` будує список подій.
- Надсилання: спершу створюємо позначку `tgsent/<ключ>` з умовою «не існує»
  (це й замок від дублів при паралельних запусках), потім шлемо; якщо
  Telegram відмовив — позначку видаляємо, щоб спробувати наступного разу.
  Якщо адресат не прив'язаний — позначка лишається (старі події не
  приходять лавиною після прив'язки).
- Перший запуск: немає `tgsent/_baseline` → усі наявні події позначаються
  без надсилання, потім створюється `_baseline`.
- Запуск: `api/notify` (сайт пінгує після нової заявки, схвалення,
  відхилення, «віддав», «отримав», «не отримав») і одразу після рішення
  в модерації бота.

## Нагадування

- GitHub Actions щоранку (9:00 Київ) викликає `POST /api/remind` із
  заголовком `x-noxon-remind` = sha256("noxon-remind:" + токен)[0..48] —
  нових секретів не треба, токен уже є і в GitHub, і у Vercel.
- `api/remind` шле Дмитру (якщо прив'язаний, інакше — адміну, як досі)
  борги на 3 дні / завтра / сьогодні; кожному прив'язаному кредитору — його
  борги, що мають повернутися завтра чи сьогодні.
- Один раз на день на адресата: позначка `tgsent/rem_<дата>_<uid>`.
- Режим `test` (ручний запуск workflow): одне повідомлення адміну —
  що отримав би Дмитро + скільки людей отримали б нагадування.

## Не входить в етап 1

Дії з Telegram (Отримав / Я віддав / новий борг), налаштування сповіщень,
щотижневий підсумок.

## Перевірка

- `node --test` для чистих модулів: маршрутизація повідомлень, розбір
  коду, події, тексти.
- Правила — живі спроби записати чуже (`tglinks` з чужим uid, `telegram`
  не-адміном, читання чужого `telegram`).
- Сайт — демо-режим (кнопка підключення показує, що це лише для хмари).
- Кінцева перевірка з реальним Telegram — на боці користувача.
