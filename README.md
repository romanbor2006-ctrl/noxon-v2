# noxon

Закритий облік боргів однієї людини — героя сайту. Спільна таблиця, яку всі бачать одночасно: кому він винен, скільки й що горить найближчим часом.

Чисті HTML, CSS і JavaScript — без збірки й npm. Firebase підключається compat-версією.

## Файли

| Файл | Відповідає за |
|---|---|
| `index.html` | каркас: порожні контейнери з id, підключення файлів |
| `style.css` | вигляд, токени кольорів, світла й темна тема |
| `config.js` | вибір сховища, ключі Firebase, дати зарплати, ліміти. **Даних про людину тут немає** |
| `storage.js` | уся робота з даними (localStorage або Firebase) і вся математика боргу |
| `app.js` | малювання сторінки й обробка натискань — не знає, де лежать дані |
| `firestore.rules` | правила доступу до бази — джерело правди |
| `firebase.json`, `.firebaserc` | для `firebase deploy` |
| `robots.txt` | заборона індексації |

## Запуск на тестових даних (етап 1)

У `config.js` стоїть `backend: "local"`. Відкрий `index.html` — дані лежать у localStorage цього браузера. Логіни `roman` (власник), `admin`, `dima`, `rostyk`, `oleh`, пароль збігається з логіном. Дві вкладки одного браузера бачать зміни одна одної одразу.

Локальне сховище імітує правила бази, тож ролі видно вже тут. Справжній захист — лише у Firestore.

Кнопка «скинути демо-дані» внизу сторінки повертає тестові записи.

## Перехід на Firebase (етап 3)

1. Firebase Console → проєкт без Analytics.
2. Authentication → увімкнути Email/Password.
3. Firestore → режим production, регіон `eur3` (**змінити потім неможливо**).
4. Веб-застосунок → ключі в `config.js` → `firebase`.
5. У `config.js` поставити `backend: "firebase"`.
6. Опублікувати правила:

   ```bash
   npm install -g firebase-tools
   firebase login
   firebase deploy --only firestore:rules
   ```

7. Authentication → Users → Add user: `rostyk@noxon.local` + пароль. Людина на сайті вводить просто `rostyk`.

**Власник.** Логін `roman` (`roman@noxon.local`) — головний адмін. Він визначається за адресою входу, а не за полем у базі, тому:

- його роль і доступ не може змінити ніхто, навіть він сам;
- якщо його профіль у базі зіпсовано, сайт при вході сам поверне `admin` і `active`;
- лише він видає й знімає роль адміна іншим (блок «Люди»);
- звичайний адмін модерує борги й людей, але не чіпає інших адмінів і самого себе.

Логін власника прописаний у двох місцях: `config.js` → `ownerLogin` і `firestore.rules` → `ownerEmail()`. Міняти — в обох.

Кожен інший новий логін заходить як кредитор.

## Досьє — у базі, а не в коді

Ім'я, дата народження, місто, робота, контакти й фото героя сайту лежать у Firestore, у документі `site/subject`. Репозиторій публічний, тому в коді цих даних немає зовсім. Правило бази віддає документ лише залогіненим і активним, а змінювати дозволяє тільки адміну.

Заповнює адмін на сайті: кнопка **«Редагувати досьє»** під іменем. Фото стискається в браузері до ~500 px і зберігається в тому ж документі (до ~400 КБ). Посилання приймаються лише з `https://`.

Після виходу сторінка стирає з розмітки все, що прийшло з бази.

## Відгуки

Зірки й текст — одне ціле, як у Google Maps: угорі середній бал і розподіл (натискання на рядок фільтрує), далі «твій відгук» або запрошення оцінити, далі стрічка з сортуванням «Найновіші / Найвищі / Найнижчі». Одна людина — один відгук: повторна публікація переписує старий, тож окремий антиспам не потрібен. Текст необов'язковий.

Колишня колекція `comments` більше не використовується і закрита правилами; старі записи можна видалити в консолі Firestore.

## Режим гостя

На екрані входу є кнопка **«Увійти як гість»**. Гість заходить анонімно (Firebase → Authentication → Sign-in method → **Anonymous**, має бути Enabled) і бачить досьє, метрики, «Що горить», реєстр, чергу, календар, ачівки й відгуки — **тільки читання**.

Імена кредиторів гостю не показуються: замість «Ростик» — «Кредитор 1». Це ширма в інтерфейсі: самі записи боргів гість читає, тож технічно грамотна людина дістане імена через консоль браузера. Якщо це неприйнятно, гостю не можна віддавати колекцію `debts` узагалі.

Гість не бачить блоків «На розгляді», «Люди», вкладки «Заявки», форми боргу й форми відгуку. Писати не може ні через сайт, ні напряму: у нього немає профілю в `users`, а всі правила запису вимагають активного профілю.

## Життєвий цикл боргу

1. Кредитор подає заявку (статус `pending`). Кожен сам за себе: борг записується лише на того, хто подає заявку, — вибору «кому» немає ні в кого, навіть в адміна. Герой сайту боргів не вносить.
2. Адмін підтверджує (`approved`) або відхиляє (`rejected`).
3. Герой сайту тисне «Віддав» і вказує суму — вона лягає в поле `claim` і ще не зараховується.
4. Кредитор тисне «Отримав» — у `payments` дописується платіж. Або «Не отримував» — заявка гасне.
5. Коли сума платежів дорівнює сумі боргу, борг закрито.

«Закрито» і «прострочено» не зберігаються — рахуються з даних. Жодна сторона не може закрити борг сама: адмін не чіпає платежі, герой сайту не підтверджує власне повернення.

## Правила бази

| Дія | Хто може |
|---|---|
| читати будь-що | залогінений і активний |
| читати борги, досьє, відгуки | також гість (анонімний вхід) |
| читати список людей | лише залогінений і активний, гостю — ні |
| створити профіль | лише свій, лише `member`, `active: true` |
| змінити ім'я, роль, доступ | адмін; роль адміна видає й знімає лише власник; власника не понизить і не вимкне ніхто |
| створити борг | активний, не герой сайту, лише собі (`creditorUid` = свій uid), лише `pending`, без платежів, час — зараз ±5 хв |
| змінити статус, суму, дату | адмін (платежі й заявки — ні) |
| поставити / скасувати `claim` | тільки `subject`, лише на підтвердженому боргу |
| зарахувати платіж | тільки той, чий uid = `creditorUid`, рівно на суму заявки |
| видалити борг | адмін |
| досьє (`site/subject`) | читати — активні; змінювати — адмін |
| відгук (`ratings/{uid}`) | лише свій (ключ = uid), 1–5 зірок + текст до 500 символів; герой сайту сам себе не оцінює; чужий видаляє лише адмін |

Старі борги без `creditorUid` адмін прив'язує до людини прямо на картці.

## Перевірка атак (етап 5)

Під **кредитором** у консолі браузера (F12). Кожен рядок має вивести `permission-denied`:

```js
const { db, auth } = Store.raw, uid = auth.currentUser.uid;
const log = (p) => p.then(() => console.log("ПРОЙШЛО — ПОГАНО"), (e) => console.log(e.code));

// борг на мільйон, одразу підтверджений
log(db.collection("debts").add({ amount: 1000000, reason: "x", creditor: "x", creditorUid: uid, author: "x", due: "2030-01-01", status: "approved", payments: [], claim: null, ts: Date.now() }));
// самопідвищення до адміна
log(db.collection("users").doc(uid).update({ role: "admin" }));
// переписати досьє
log(db.collection("site").doc("subject").update({ name: "Хакер" }));
// оцінка за іншого
log(db.collection("ratings").doc("ЧУЖИЙ_UID").set({ value: 5, text: "", user: "x", ts: Date.now() }));
// чуже підтвердження повернення (борг іншого кредитора із заявкою героя сайту)
log(db.collection("debts").doc("ID_ЧУЖОГО_БОРГУ").update({ claim: null, payments: [{ amount: 1, ts: Date.now() }] }));
```

Під **героєм сайту** — платіж напряму, без кредитора:

```js
Store.raw.db.collection("debts").doc("ID_БОРГУ").update({ payments: [{ amount: 500, ts: Date.now() }] }).catch((e) => console.log(e.code));
```

## Telegram-нагадування

Бот у папці `bot/` щодня о 9:00 за Києвом перевіряє борги й пише в Telegram, якщо до дати повернення лишилось **3 дні, 1 день або настав сам день**. Решту часу мовчить. Усе, що горить, — одним повідомленням. Після дати повернення бот не нагадує.

Запускає GitHub Actions (`.github/workflows/remind.yml`), безкоштовно. Бот заходить у Firebase **анонімно**, як гість сайту, і лише читає борги — ключів Firebase не потрібно. Дні й залишки рахує тим самим `storage.js`, що й сайт.

**Секрети** (Settings → Secrets and variables → Actions):
- `TELEGRAM_BOT_TOKEN` — токен від @BotFather;
- `TELEGRAM_CHAT_ID` — кому надсилати. Щоб змінити отримувача, заміни лише цей секрет; людина має спершу натиснути **Start** у боті.

**Перевірити вручну:** Actions → «Нагадування в Telegram» → **Run workflow** → режим `test` — повідомлення прийде завжди, навіть якщо нічого не горить.

**Локально**, без секретів — лише показати текст:

```bash
node bot/remind.js --dry-run --mode=test
```

Тести: `node --test bot/reminders.test.js bot/firestore.test.js`.

Обмеження: розклад GitHub може запізнюватися на 5–30 хвилин; після 60 днів без комітів GitHub вимикає розклад (вмикається одним кліком на вкладці Actions).

## Публікація

GitHub Pages: публічний репозиторій, файли в корені, Settings → Pages → гілка `main`, папка `/`. Секретів у коді немає — доступ тримають правила бази.

Після кожного заливання збільш `?v=` в усіх рядках `index.html`, інакше люди бачитимуть стару копію з кешу.

Після переходу на свій домен: Firebase → Authentication → Settings → Authorized domains → додати домен. Інакше вхід не працюватиме ні в кого.
